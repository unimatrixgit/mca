# Imperial Navigator renderer

Current release: **1.2.0-graphical**, Paper 1.21.8 / Java 21, with optional backend Floodgate. Java uses the graphical inventory renderer; the earlier Java dialog/book navigation route is retired. Install alongside the matching NativeMenus bridge in Core, Essentials, NPC and Lobby. `/navigator` routes to the current backend's player menu. `/dune` and the navigator item use the same player menu on game backends; the lobby Guild liaison opens its configured planet list.

Java receives six graphical cards per page with owner-bound hit slots and separate review/confirmation screens. The optional v7 pack provides the title background and navigation models; declining it leaves readable item cards. The display inventory is real server UI, but every transfer into or out of it, click type and drag is cancelled; decorative stacks do not become player items. Bedrock receives native SimpleForms with image buttons and separate detail/confirmation views, using the independent imperial skin.

Each view is bound to the player UUID, an opaque 256-bit callback token, exact model identity, current permission supplier, render revision and 30-second expiry. A state-changing callback is single-use and queued to the main thread, then rechecks the player connection, exact current view, expiry and permissions. Replacing or closing the screen, opening another inventory, cancellation and logout invalidate earlier views. Older Bedrock responses and callback commands cannot operate a later view. Existing economy escrow and moderation permission/snapshot checks remain authoritative.

Typewriter remains a separate authored conversation/quest engine. The 6 November inventory finds it on Caladan, Kaitain and Sigma Draconis IV only; it is not automatically installed or required by the transactional navigator. DuneMenus supplies the bridge for existing transaction callbacks and does not turn authored conversations into financial or staff authority.

The additive published Java pack contains the `dunerealms:imperial_menus` bitmap font. Java custom fonts do not transfer to Bedrock; form buttons use HTTPS DuneRealms asset images. Current artifact hashes, live route inventory and the pending Java/Bedrock appearance, focus and hit-testing matrix are in [the task 326 acceptance record](../docs/menu-acceptance-326/README.md). Package/unit/HTTP checks do not claim a client test. Preserve the existing live renderer and pack when preparing unrelated Core or staff changes.

A private optional discovery adapter calls the authenticated website endpoint with a current view HMAC proof and actual UUID. It never credits game currency or broadcasts a code. The website owns eligibility, the global winner and account-bound code redemption. Secrets are read from the existing Essentials website bridge file and are never logged.
